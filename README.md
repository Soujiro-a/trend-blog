# 실시간 이슈 블로그 자동화

실시간 검색어 상위 키워드를 모아 글을 쓰고, **Blogger 에 임시저장**까지 해 둡니다.
공개는 하지 않습니다 — 검토 후 직접 '게시' 버튼을 누르는 구조입니다.

```
 실시간 검색어 5개 소스          중복/민감 주제 필터        Claude API
 ┌──────────────────┐         ┌──────────────┐        ┌──────────┐
 │ 구글 트렌드       │         │ 14일 내 중복  │        │ 리서치    │
 │ 시그널(signal.bz) │ ──합산─▶│ 사건사고 제외 │──상위──▶│ 글 작성   │
 │ 네이트            │  점수화  │ 기사 2건 미만 │  N개    │ 제목/태그 │
 │ 네이버 뉴스 랭킹   │         │   제외        │        └────┬─────┘
 │ 구글 뉴스         │         └──────────────┘             │
 └──────────────────┘                                      ▼
                                                    Blogger 임시저장
                                          (GitHub Actions 가 매일 06:00 KST 자동 실행)
```

**초기 비용 0원으로 시작할 수 있습니다.** 도메인은 지금 사지 않아도 됩니다
([아래 설명](#도메인은-지금-사지-않아도-됩니다)).

---

## 1. 준비 (최초 1회, 30~40분)

### 1단계 — Blogger 블로그 만들기 (5분, 무료)

[blogger.com](https://www.blogger.com) 에서 구글 계정으로 블로그를 만듭니다.
주소는 `원하는이름.blogspot.com` 이 됩니다. 나중에 개인 도메인으로 바꿔도
주소가 자동 연결되니 지금은 아무 이름이나 괜찮습니다.

### 2단계 — Blogger API 권한 받기 (15분)

[Google Cloud Console](https://console.cloud.google.com) 에서:

1. 새 프로젝트 생성
2. **API 및 서비스 → 라이브러리** → "Blogger API v3" 검색 → **사용 설정**
3. **OAuth 동의 화면**(최신 콘솔에서는 *Google 인증 플랫폼*) → User Type **외부** → 앱 이름 아무거나 → 저장
   → 그다음 **대상(Audience)** 페이지에서 **앱 게시 → 프로덕션으로 전환**

   게시하려면 **브랜딩** 페이지에 아래가 모두 채워져 있어야 합니다.
   앱 이름 / 사용자 지원 이메일 / 개발자 연락처 이메일 /
   **애플리케이션 홈페이지 URL** / **개인정보처리방침 URL**

   뒤의 두 URL 은 블로그에 페이지를 만들어 쓰면 됩니다. 붙여넣기용 템플릿을
   [`pages/`](pages) 에 넣어뒀습니다 (`about.html`, `privacy-policy.html`).
   개인정보처리방침은 **애드센스 심사에도 어차피 필수**라 미리 만들어 두면 두 번 일하지 않습니다.

   > **이 단계를 건너뛰지 마세요.** 게시 상태가 '테스트'인 동안 발급된 refresh token 은
   > **7일 뒤 만료**됩니다([구글 문서](https://developers.google.com/identity/protocols/oauth2)).
   > 그러면 매주 인증을 다시 해야 해서 자동화가 무너집니다. 프로덕션으로 바꾸면 만료되지 않습니다.
   >
   > 게시해도 구글 심사를 받는 게 아니라서 로그인할 때 '확인되지 않은 앱' 경고는 계속 뜹니다.
   > 본인만 쓰는 용도라 그대로 진행하면 됩니다(미인증 앱은 사용자 100명까지 허용).
4. **사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID**
   → 애플리케이션 유형 **데스크톱 앱** → 만들기
   > 기본값인 '웹 애플리케이션'으로 만들면 인증 단계에서 `400 오류: redirect_uri_mismatch`
   > 가 납니다. 구글은 임의 포트로 돌아오는 주소를 **데스크톱 앱 유형에만** 허용합니다.
   > 이미 웹 유형으로 만드셨다면 [아래](#redirect_uri_mismatch-오류가-난다면) 참고.
5. 나온 **클라이언트 ID** 와 **클라이언트 보안 비밀번호**를 복사

그다음 이 폴더에서:

```bash
pip install -r requirements.txt
python scripts/get_blogger_token.py
```

브라우저가 열리면 블로그 소유 계정으로 승인하세요.
끝나면 **GitHub Secrets 에 넣을 값 4개**가 터미널에 출력됩니다.

> 이 값들은 비밀번호와 같습니다. 채팅창이나 공개 저장소에 붙여넣지 마세요.

#### `redirect_uri_mismatch` 오류가 난다면

클라이언트를 '웹 애플리케이션' 유형으로 만든 경우입니다. 둘 중 하나로 해결합니다.

- **(권장) 데스크톱 앱 유형으로 새로 만들기** — 사용자 인증 정보에서 클라이언트 ID를
  하나 더 만들면 됩니다. OAuth 동의 화면은 다시 설정하지 않아도 됩니다.
- **지금 클라이언트를 그대로 쓰기** — 해당 클라이언트를 열어 **승인된 리디렉션 URI**에
  `http://localhost:8080` 을 추가하고 저장한 뒤 (반영에 1~2분 걸릴 수 있습니다):

  ```bash
  python scripts/get_blogger_token.py --port 8080
  ```

#### "Google에서 확인하지 않은 앱입니다" 경고

본인이 만든 테스트 앱이라 정상입니다. **고급** → **{앱이름}(으)로 이동(안전하지 않음)**.

#### `403 오류: access_denied` / "앱이 Google의 인증 절차를 완료하지 않았습니다"

앱이 아직 **테스트** 상태이고 로그인하려는 계정이 테스트 사용자 목록에 없습니다.

**테스트 사용자를 추가하지 말고, 2단계 3번대로 앱을 프로덕션으로 게시하세요.**
테스트 사용자로 추가해서 받은 토큰은 7일 뒤 만료되므로 근본 해결이 아닙니다.

Google Cloud → **Google 인증 플랫폼 → 대상(Audience)** → **앱 게시** → 확인.
게시한 *뒤에* 토큰 발급 스크립트를 다시 실행해야 만료되지 않는 토큰을 받습니다.

### 3단계 — Claude API 키 발급 (5분)

[console.anthropic.com](https://console.anthropic.com) → **API Keys** → 새 키 생성.
결제 수단을 등록하고 **사용량 한도(Usage limit)를 월 $20 정도로 걸어두세요.**
설정 실수로 비용이 폭주하는 걸 막아줍니다.

### 4단계 — GitHub 저장소에 올리기 (10분)

```bash
git init
git add .
git commit -m "feat: 실시간 이슈 블로그 자동화"
```

GitHub 에서 **비공개(Private)** 저장소를 만들고 푸시합니다.
(비공개여도 Actions 무료 한도 월 2,000분 안에서 충분히 돌아갑니다. 이 작업은 월 30분 정도 씁니다.)

그다음 저장소 **Settings → Secrets and variables → Actions** 에서
`New repository secret` 으로 5개를 등록합니다:

| 이름 | 값 |
|---|---|
| `ANTHROPIC_API_KEY` | 3단계에서 만든 키 |
| `BLOGGER_CLIENT_ID` | 2단계 출력값 |
| `BLOGGER_CLIENT_SECRET` | 2단계 출력값 |
| `BLOGGER_REFRESH_TOKEN` | 2단계 출력값 |
| `BLOGGER_BLOG_ID` | 2단계 출력값 |

### 5단계 — 첫 실행 확인

저장소 **Actions** 탭 → `실시간 이슈 글 임시저장` → **Run workflow**.
2~3분 뒤 Blogger 관리자 화면의 **'임시저장' 탭**에 글이 들어와 있으면 성공입니다.

이후로는 **매일 06:00 KST 에 자동 실행**됩니다. 아침에 일어나면 초안이 준비돼 있습니다.
PC는 꺼져 있어도 됩니다.

> GitHub 예약 실행은 부하에 따라 5~20분 늦게 뜨는 게 정상입니다. 더 일찍 받고 싶으면
> `.github/workflows/draft.yml` 의 `cron` 을 `"40 20 * * *"`(05:40 KST) 처럼 앞당기세요.

## 2. 애드센스 신청

애드센스는 **글이 어느 정도 쌓인 뒤**에 신청하는 게 승인률이 높습니다.
**직접 검토해서 공개한 글이 20~30개쯤 됐을 때** 신청하세요.

Blogger 관리 화면 왼쪽 메뉴에 **수익** 항목이 있고, 거기서 바로 신청됩니다
(구글 서비스라 별도 사이트 연동 작업이 없습니다).

### 승인 전에 채워야 하는 것

애드센스 심사에서 실제로 자주 막히는 항목들입니다:

- **개인정보처리방침 페이지** — 필수입니다. 없으면 거의 반려됩니다.
  → [`pages/privacy-policy.html`](pages/privacy-policy.html) 을 Blogger 페이지에 붙여넣으세요
- **소개 / 문의 페이지** — 운영자가 누구인지 알 수 있어야 합니다.
  → [`pages/about.html`](pages/about.html)
- 글이 특정 주제로 어느 정도 묶여 있을 것 — 아무 주제나 섞이면 불리합니다.

### 솔직하게 알아둘 점

구글은 **"검색 순위만 노린 대량 생산 콘텐츠"** 를 정책 위반(scaled content abuse)으로 봅니다.
AI 로 썼다는 것 자체는 문제가 아니지만, **원본 기사를 요약만 해서 하루 수십 개씩 올리면**
색인 제외나 애드센스 반려로 이어질 수 있습니다.

그래서 이 시스템은 이렇게 만들었습니다:

- 글에 **배경 설명·용어 풀이·FAQ·앞으로 볼 지점**을 넣어 기사에 없는 값을 더합니다
- 참고한 기사를 **출처로 명시**합니다 (실제 주소가 있는 것만 링크로 걸고, 나머지는 매체명+제목)
- AI 작성 사실은 **소개 페이지**에 밝혀 둡니다 (글마다 붙이면 읽는 사람이 거부감을 느낍니다)
- 사건사고·개인 사생활·의혹 관련 키워드는 **자동으로 걸러냅니다**
  (명예훼손 위험 + 애드센스 '충격적인 콘텐츠' 정책 때문입니다)

그래도 **공개 전 검토는 꼭 직접 하세요.** 사실관계가 틀렸거나 내용이 얄팍한 글은
올리지 말고 버리는 편이 장기적으로 이득입니다. 그래서 자동 공개가 아니라
임시저장까지만 하도록 만들었습니다.

### 도메인은 지금 사지 않아도 됩니다

`blogspot.com` 주소로도 애드센스 승인이 납니다. 개인 도메인(`.com` 기준 **연 1.5~2만원**)은
신뢰도와 SEO에 조금 유리하지만, **지금 살 필요는 없습니다.**

Blogger 는 나중에 개인 도메인을 연결해도 기존 주소에서 자동 전환해 주기 때문에,
**트래픽이 실제로 붙는 게 확인된 뒤에 사는 게 낫습니다.**
사기로 하시면 [Cloudflare Registrar](https://www.cloudflare.com/products/registrar/) 나
가비아에서 구입 후 Blogger 설정 → 맞춤 도메인에서 연결하면 됩니다.

**지금 당장 들어가는 돈은 Claude API 비용뿐입니다.**

## 3. 점검

### 매일 아침 5분

06:00 에 초안 4개가 임시저장함에 들어와 있습니다.

1. **Blogger 임시저장함** — 읽고 **2~3개만** 공개. 나머지는 지웁니다
2. 공개한 글마다 **Search Console → URL 검사 → 색인 생성 요청** (글당 20초)

> 2번을 건너뛰지 마세요. 실시간 이슈는 검색 유입 수명이 **1~3일**이라,
> 색인이 며칠 늦으면 글이 죽은 채로 공개됩니다. 색인 요청하면 보통 몇 시간 안에 잡힙니다.
>
> 매일 볼 시간이 없다면 글 생산량을 줄이고(`posts_per_run: 2`) 수명이 긴 주제
> (용어 해설·제도 안내) 위주로 필터를 조정하는 편이 낫습니다.

### 주 1회 5분

1. **GitHub Actions 탭** — 빨간 ✗ 가 있는지. 각 실행의 Summary 에 그날 어떤
   키워드를 골랐고 무엇을 걸러냈는지 보고서가 붙습니다
2. **Anthropic Console 사용량** — 예상 범위(월 $11 안팎) 안인지
3. **Search Console → 실적** — 어떤 글에 유입이 붙는지. 패턴이 보이면 필터를 조정합니다
4. (애드센스 승인 후) **애드센스 대시보드** — 수익 추이

실행이 실패하면 GitHub 이 자동으로 메일을 보냅니다. 따로 감시할 필요 없습니다.

> **한 가지 주의:** GitHub 은 **60일 동안 저장소 활동이 없으면 예약 실행을 자동 중지**합니다.
> 이 시스템은 매 실행마다 이력을 커밋하므로 보통 괜찮지만, 중지 예고 메일이 오면
> Actions 탭에서 `Enable workflow` 를 눌러주세요.

## 4. 비용

| 항목 | 비용 |
|---|---|
| Blogger | 무료 |
| GitHub Actions | 무료 (월 2,000분 중 약 30분 사용) |
| 실시간 검색어 수집 | 무료 (공개 RSS/API) |
| 도메인 | 선택 — 연 1.5~2만원 |
| **Claude API** | **아래 표 참고** |

기본 설정(매일 1회 × 4개 = **하루 4개 초안**) 기준:

| 모델 | 글 1개당 | 하루 | 월 예상 |
|---|---|---|---|
| `claude-opus-5` (기본) | 약 $0.09 | 약 $0.35 | **약 $11** |
| `claude-sonnet-5` | 약 $0.04 | 약 $0.15 | **약 $5** |

비용을 줄이려면 `config.yaml` 에서 둘 중 하나를 바꾸세요:

```yaml
run:
  posts_per_run: 2        # 하루 4개 → 2개

writer:
  model: claude-sonnet-5  # 품질을 조금 낮추고 비용 절반 이하로
```

실행 횟수 자체를 줄이려면 `.github/workflows/draft.yml` 의 `cron` 줄을 지우면 됩니다.

> 초안을 넉넉히 만들어 **골라서 공개하는 것**이 기본 설정입니다.
> 4개를 전부 공개하지 마시고 2~3개만 고르세요. 안 쓴 초안은 지우면 됩니다.

python -m src.main --count 1

## 6. 설정 조정

전부 `config.yaml` 에 있습니다. 자주 만질 만한 것들:

| 설정 | 의미 |
|---|---|
| `run.posts_per_run` | 하루에 만들 초안 개수 (실행이 1회라 이 값이 곧 하루 생산량) |
| `trends.sources` | 소스별 가중치. `0` 으로 두면 그 소스를 끕니다 |
| `filters.sensitive_patterns` | 차단 키워드. 너무 많이 걸러지면 몇 개 빼세요 |
| `dedupe.history_days` | 같은 주제를 다시 안 쓸 기간 (기본 14일) |
| `writer.model` | `claude-opus-5` / `claude-sonnet-5` |
| `writer.target_length` | 최소 글자수 (기본 1900자) |
| `writer.footer_note` | 글 맨 아래 안내 문구. `""` 로 두면 아무것도 안 붙습니다 |
| `publish.draft_only` | **`true` 로 두세요.** `false` 면 바로 공개됩니다 |

어떤 키워드가 왜 걸러졌는지는 실행할 때마다 `data/last_run.md` 에 기록됩니다.
필터가 너무 빡빡하다 싶으면 이 파일을 보고 조정하세요.

## 7. 문제가 생기면

| 증상 | 원인과 해결 |
|---|---|
| `액세스 토큰 발급 실패` | refresh token 만료. 먼저 OAuth 앱이 **프로덕션으로 게시**돼 있는지 확인(테스트 상태면 7일마다 만료됩니다). 그다음 `python scripts/get_blogger_token.py` 재실행 후 Secret 갱신 |
| 일주일마다 인증이 풀림 | OAuth 게시 상태가 '테스트'입니다. 프로덕션으로 게시한 뒤 토큰을 **새로** 발급받으세요 |
| `환경변수 ... 설정되지 않았습니다` | GitHub Secrets 이름 오타 확인 (대소문자 구분) |
| `키워드 수집 부족` | 소스 사이트가 일시적으로 막힌 경우. 다음 실행에 대개 복구됩니다 |
| 글이 하나도 안 써짐 | 필터가 다 걸러낸 경우. `data/last_run.md` 의 '걸러낸 키워드' 확인 |
| 예약 실행이 멈춤 | 60일 무활동으로 비활성화됨. Actions 탭에서 `Enable workflow` |
| 매번 같은 키워드 | `data/history.json` 이 커밋되는지 확인 (Actions 권한 `contents: write`) |
